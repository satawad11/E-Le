## สิ่งที่พบและแก้ในรอบนี้

### A · ลบประเภทการลาแล้วสิทธิและยอดวันลาของทุกคนหายไปด้วย (ข้อมูลสูญหาย)

`leave_policies` และ `leave_balances` ผูกกับ `leave_types` แบบ **cascade** ด่านเดิมตรวจแค่
"มีใบลาหรือยัง" ประเภทการลาที่ตั้งสิทธิไว้แล้วแต่ยังไม่มีใครลา จึงลบได้ และการลบหนึ่งครั้ง
พา **นโยบายสิทธิทุกฉบับและยอดวันลา (รวมยอดยกมา) ของทุกคน** ของประเภทนั้นหายไปเงียบ ๆ

ยืนยันด้วยการทดลองจริงบนเครื่องพัฒนา: สร้างประเภท + นโยบาย + ยอดคงเหลือ แล้วเรียก
`DELETE /api/admin/leave-types/{id}` → คืน 200 และทั้งสามแถวหายพร้อมกัน

**แก้:** ปฏิเสธการลบเมื่อมีนโยบายหรือยอดวันลาอ้างถึง พร้อมบอกจำนวนและทางออก
(ปิดนโยบายที่หน้า "นโยบายสิทธิการลา" แทนการลบประเภทการลา) · ประเภทที่ยังไม่มีใครใช้ยังลบได้ตามเดิม

### B · ตัวแปรของแบบฟอร์มค้างอยู่หลังต้นทางหายไป

ตัวแปรที่ระบบสร้างให้ตามข้อมูลจริง (`stats.leave_type_<id>.*`, `extra.<คีย์>`,
`approval.step{N}.*`) ไม่เคยถูกปิดเมื่อประเภทการลาถูกลบ ช่องเฉพาะถูกถอด หรือสายอนุมัติถูกลดขั้น
ผู้ดูแลยังเลือกวางบนแบบฟอร์มได้ทั้งที่ไม่มีค่ามาเติมอีกแล้ว และการตรวจก่อนเผยแพร่ก็ไม่ทัก
เพราะรหัสฟิลด์ "มีอยู่จริง" ในพจนานุกรม

**แก้:** `FieldDictionarySynchronizer` ปิดตัวแปรที่ต้นทางหายไปทุกครั้งที่ซิงก์ — **ปิดเท่านั้น ไม่ลบ**
แบบฟอร์มเวอร์ชันเก่าที่วางไว้ยังพิมพ์ได้เหมือนเดิม และการตรวจก่อนเผยแพร่จะรายงานเป็นข้อผิดพลาด
ให้แก้ก่อนออกเวอร์ชันใหม่ · รันบนเครื่องพัฒนาแล้ว: ตัวแปรที่ใช้งานอยู่ 184 → 178 (ปิดของประเภทที่ถูกลบไป 6 รายการ)

### C · หน้ายื่นใบลาไม่บอกกติกาของนโยบายก่อนกรอก

กติกาทั้งหมดมากับข้อมูลสิทธิอยู่แล้ว (`/leaves/balances` แนบนโยบายมาเต็มก้อน) แต่หน้าจอไม่ใช้เลย
ผู้ใช้จึงกรอกจนเสร็จแล้วค่อยถูกปฏิเสธตอนกดส่ง — ต้องแนบหลักฐาน / ลาครึ่งวันไม่ได้ /
เกินเพดานต่อครั้ง / ยื่นล่วงหน้าไม่พอ

**แก้:**
- แสดงหลักเกณฑ์ของประเภทที่เลือกไว้ใต้แถบสิทธิ และ **เน้นข้อที่คำขอปัจจุบันกำลังชนเกณฑ์**
- ป้ายช่องเอกสารแนบเปลี่ยนจาก "(ถ้ามี)" เป็น "**\*** (ชนิดหลักฐานที่กำหนด)" เมื่อจำนวนวันถึงเกณฑ์
- ซ่อนตัวเลือกครึ่งวันเมื่อนโยบายไม่อนุญาต และดึงค่ากลับเป็นเต็มวันให้เองเมื่อสลับไปประเภทที่ลาครึ่งวันไม่ได้

### D · โค้ดที่ตายแล้วซึ่งอิงกติกาที่เลิกใช้

`App\Services\LeaveBalanceService` คำนวณโควตาตามสัดส่วนจาก `leave_types.max_days`
ซึ่งเป็นแบบจำลองก่อนมี `leave_policies` — ไม่มีอะไรในระบบเรียกใช้เลยแม้แต่ที่เดียว
(ตรวจทั้ง `app/`, `routes/`, `database/`, `tests/`) การมีอยู่ของมันคือกับดักสำหรับคนที่มาอ่านทีหลัง
เพราะดูเหมือนเป็นที่คำนวณสิทธิของระบบ

**แก้:** ลบทิ้ง (ประวัติยังอยู่ใน git หากต้องการกลับมาดู)

## สิ่งที่พบแต่ยังไม่แก้ และเหตุผล

### 1. คอลัมน์บน `leave_types` ที่ไม่มีตรรกะใดอ่าน

| คอลัมน์ | สถานะ |
|---|---|
| `requires_doc` | บันทึกและตรวจ validation ได้ แต่ **ไม่มีโค้ดใดอ่าน** — กติกาจริงคือ `leave_policies.attachment_required_after_days` · ไม่มีช่องกรอกในหน้าจอ จึงไม่ใช่กับดักที่ผู้ดูแลกดแล้วไม่เกิดอะไร |
| `is_prorated` | เดิมมีไว้ให้ `LeaveBalanceService` ใช้ · หลังลบบริการนั้นแล้วไม่มีอะไรอ่านอีก |
| `notice_period_days`, `allow_past_dates`, `exclude_holidays`, `require_attachment_after_days`, `max_days` | ไม่ใช่กติกาที่ใช้ตัดสิน แต่เป็น **ค่าตั้งต้นครั้งเดียว** ตอน `LeavePolicyService::resolve()` สร้างนโยบายให้อัตโนมัติ — หน้าจอปัจจุบันอธิบายเรื่องนี้ไว้แล้ว (`ค่าตั้งต้น (วัน)` เป็นแบบอ่านอย่างเดียวตอนแก้ไข พร้อมข้อความชี้ไปหน้านโยบาย) |

การล้างคอลัมน์เหล่านี้ต้องแก้ schema ซึ่ง `PROJECT_RULES` ห้ามในช่วง PRODUCTION PHASE
จึงบันทึกไว้เป็นงานของรอบที่เปิด phase ใหม่ ไม่ใช่ปล่อยผ่านเงียบ ๆ

### 2. ช่องวันที่ที่ตั้งเป็น "จำเป็น" ยังไม่บังคับฝั่งเบราว์เซอร์

`ThaiDatePicker` ไม่รับ `required` ผู้ใช้จึงกดส่งได้แล้วถูกเซิร์ฟเวอร์ปฏิเสธ (ซึ่งตรวจครบถูกต้อง)
เป็นเรื่องความสะดวก ไม่ใช่ช่องโหว่ของกติกา — ต้องแก้ที่คอมโพเนนต์ซึ่งใช้ร่วมกันหลายหน้า
จึงแยกเป็นงานของตัวเองแทนการแก้เฉพาะหน้านี้
