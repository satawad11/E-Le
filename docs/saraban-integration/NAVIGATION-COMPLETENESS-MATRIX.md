## 2. ช่องว่างที่พบ

### 2.1 🔴 ไม่มีคิว "หนังสือที่รอฉันดำเนินการ" — ตัวปิดกั้นการใช้งานจริง

**นี่คือช่องว่างเดียวที่ทำให้งานประจำวันทำไม่ได้**

ทะเบียนหนังสือกรองได้เฉพาะ **ทิศทาง** และ **สถานะ** และคัดด้วยหน่วยงานเจ้าของ
เรื่องเท่านั้น (`DocumentController::index`) · **ไม่มีทางถามว่า "หนังสือฉบับใด
รอฉันพิจารณาหรือลงนามอยู่"**

ตรวจแล้วว่าไม่มีจริงทั้งสามชั้น:

| ชั้น | ผลตรวจ |
|---|---|
| หน้าจอ | ไม่มี view ใดแสดงคิวของผู้ใช้ |
| เส้นทาง API | `grep` หา `assignee_user_id` ใน `app/Http/Controllers` และ `app/Services/Saraban` — **ไม่พบเลย** |
| เมนู | ไม่มีรายการใดใน `TREE` |

`DocumentWorkflowService::stateFor()` ตอบได้ว่า "ฉันทำอะไรกับหนังสือ**ฉบับนี้**ได้บ้าง"
แต่ไม่มีคำถามย้อนกลับว่า "หนังสือฉบับใดบ้างที่ฉันทำอะไรได้"

**ผลต่อผู้ใช้จริง:** รองผู้อำนวยการและผู้อำนวยการ — ซึ่งงานประจำวันคือการพิจารณา
และลงนาม — **ต้องเปิดทะเบียนแล้วไล่เปิดทีละฉบับเพื่อหาว่าฉบับไหนถึงคิวตน**
ตรงกับ §4.7 และ §3.4/§3.5 ที่ระบุเมนู "รอพิจารณา / รอลงนาม" เป็นเมนูหลักของสองบทบาทนี้

**การแก้:** เพิ่ม endpoint + หน้าจอ + เมนูหนึ่งรายการ · **ใช้ตัวตัดสินเดิม**
(`WorkflowEngine::availableTransitions`) เป็นเกณฑ์ ไม่สร้างตรรกะสิทธิ์ใหม่

### 2.2 แดชบอร์ดสารบรรณ — ไม่ทำ

§4.1 เสนอแดชบอร์ดพร้อมตัวเลขสรุปหลายช่อง · **ไม่ทำในรอบนี้** เพราะ §16 ห้าม
เพิ่มเมนูที่ไม่จำเป็น และคิวงานตามข้อ 2.1 ตอบคำถาม "วันนี้ฉันต้องทำอะไร" ได้แล้ว ·
แดชบอร์ดที่ซ้ำกับคิวจะเพิ่มที่ให้ดูแลโดยไม่เพิ่มความสามารถ

### 2.3 รายงานยังไม่มีปุ่มส่งออก

`saraban.report.export` **มีในสารบัญสิทธิ์แต่ไม่มี route ใดใช้** — สิทธิ์ที่ไม่มี
เส้นทางบังคับใช้ คือสิทธิ์ที่หลอกผู้ดูแลว่าควบคุมอะไรอยู่

ไม่แก้ในรอบนี้ (นอกขอบเขต navigation) แต่บันทึกเป็น **RISK-69**

### 2.4 `saraban.audit.view` ไม่มี route ใดใช้

เช่นเดียวกับข้อ 2.3 · ประวัติการดำเนินการแสดงอยู่ในหน้ารายละเอียดหนังสือผ่าน
`stateFor()['history']` ซึ่งคุมด้วย `DocumentPolicy::view()` · บันทึกเป็น **RISK-70**

## 3. รายการที่เอกสารตรวจรับระบุผิด — ต้องแก้เอกสาร

`PRODUCTION-ACCEPTANCE.md` หัวข้อ ฉ. ระบุสามรายการว่า "มี API ครบ ไม่มีหน้าจอ"
**ซึ่งไม่จริงแล้ว** — ตรวจการเชื่อมต่อจริงในโค้ดพบว่าทั้งสามมีหน้าจอและถูกเรียกใช้:

| รหัส | ที่เอกสารบอก | ความจริง |
|---|---|---|
| RISK-48 | ไม่มีหน้าจอปกปิดข้อมูล | `DocumentTools.vue` มีส่วนสร้างสำเนาปกปิดพร้อมเลือกพื้นที่บน `PdfWorkspace` |
| RISK-47 | ไม่มีหน้าจอมุมมองที่บันทึก/เปรียบเทียบ | `SavedViews.vue` อยู่ใน `DocumentsView` · การเปรียบเทียบอยู่ใน `DocumentTools` |
| RISK-51 | ไม่มีหน้าจออายัด/คิวทำลาย | `RetentionPanel.vue` อยู่ทั้งในหน้ารายละเอียดและศูนย์เฝ้าระวัง |

> เอกสารตรวจรับที่ระบุความสามารถผิด อันตรายพอกับความสามารถที่ขาดไป — ผู้ตัดสินใจ
> อาจเลื่อนการขึ้นระบบเพราะเชื่อว่ายังขาดสิ่งที่มีอยู่แล้ว

ช่องว่างเดียวที่เป็นตัวปิดกั้นการใช้งานจริง · แก้ครบสามชั้น

**ไม่สร้างกติกาสิทธิ์ใหม่แม้แต่ข้อเดียว** — ใครทำอะไรได้ตัดสินด้วย

> ถ้าคิวตัดสินเอง มันจะแสดงงานที่กดแล้วถูกปฏิเสธ หรือซ่อนงานที่ทำได้จริง —
> ทั้งสองอย่างแย่กว่าไม่มีคิวเลย

**ข้อจำกัดที่บอกตรง ๆ บนหน้าจอ:** การตัดสินต้องถามเครื่องยนต์ทีละเรื่อง จึงจำกัด
การไล่ตรวจไว้ที่ 300 เรื่องที่กำลังเดินอยู่ · เมื่อเกิน หน้าจอ **ขึ้นคำเตือนว่ารายการ
อาจไม่ครบ** แทนที่จะตัดท้ายเงียบ ๆ ให้ผู้ใช้เชื่อว่าไม่มีงานเหลือ
