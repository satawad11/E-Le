# SIGNATURE VERIFICATION — Gap Matrix

**Source of Truth:** `SARABAN-V1.2-EXISTING-SYSTEM-MODULE-MASTER.md` §8, §12, §14, §24, §26
**วันที่สำรวจ:** 2026-09-05 · สำรวจโค้ดจริงก่อนเขียนแผน ไม่ได้อ่านจากรายงานเก่า

---

## สิ่งที่ระบบมีอยู่จริงวันนี้

สำรวจแล้วเจ็ดจุด · **ระบบมีรากฐานที่ดีกว่าที่คาด** แต่ขาดชั้น "การตรวจสอบ" ทั้งชั้น

| ชิ้นส่วน | ที่อยู่ | ทำอะไรได้จริง |
|---|---|---|
| การลงนาม | `SignatureService::sign()` | ตรวจ step-up ซ้ำในบริการเอง · วางลายเซ็นเป็น**พิกัดเส้น ไม่ใช่ภาพ** · เรนเดอร์เวอร์ชันใหม่ฝั่ง server |
| หลักฐานการลงนาม | `SignatureEvidence` | ผู้ลงนาม/ตำแหน่ง/หน่วยงาน/อำนาจ/เวลา/วิธี/เวอร์ชัน/แฮช/token/IP/UA · **แก้และลบไม่ได้ที่ระดับโมเดล** |
| เวอร์ชันเอกสาร | `DocumentVersion` + `DocumentService` | ทุกฉบับเป็นแถวใหม่เสมอ · `file_hash` = `sha256` ของเนื้อไฟล์ |
| ความสมบูรณ์ของไฟล์ | `SignatureService::evidenceIsIntact()` | เทียบแฮชไฟล์ปัจจุบันกับที่บันทึกไว้ — **คืนค่า boolean เดียว** |
| ตรวจสอบสาธารณะ | `DocumentVerificationController::verify()` | คืนเลขหนังสือ/เรื่อง/ผู้ลงนาม + `is_valid` ที่คิดจาก finalized/cancelled/content_hash |
| ลายนิ้วมือเนื้อหา | `DocumentVerificationService` | ผนึก `content_hash` ของ **เมทาดาทา** ตอนออกฉบับสมบูรณ์ |
| อำนาจลงนาม | `AuthorityResolver::hasAuthorityOver(..., $on)` | **รับวันที่ย้อนหลังได้อยู่แล้ว** — ใช้ตรวจอำนาจ ณ วันที่ลงนามได้ทันที |
| ยืนยันตัวตนซ้ำ | `StepUpAuthentication` | `assuranceReferenceFor()` คืน token id + เวลา — บันทึกไว้ในหลักฐานแล้ว |

**สิ่งที่ไม่มีเลย:** ไม่มีบริการตรวจสอบลายเซ็น ไม่มีสถานะการตรวจสอบ ไม่มี certificate
ไม่มี trusted timestamp ไม่มีการตรวจลำดับการลงนาม ไม่มีวงจรเพิกถอน และ
`Document::STATUS_CANCELLED` **มีนิยามแต่ไม่มีโค้ดที่ไหนตั้งค่านี้เลย**

## Gap Matrix

| # | REQUIREMENT | CURRENT IMPLEMENTATION | MISSING | RISK | ACTION |
|---|---|---|---|---|---|
| 1 | Signature Verification Service | ไม่มี · มีเพียง `evidenceIsIntact()` คืน boolean | บริการรวมที่ตอบได้ว่า "ลายเซ็นนี้เชื่อถือได้เพราะอะไร" | **สูง** — ผู้ใช้เห็นว่ามีลายเซ็น แต่ไม่มีใครตอบได้ว่ามันยังใช้ได้ไหม | สร้าง `SignatureVerificationService` คืนสถานะ + รายการตรวจรายข้อ |
| 2 | Document Integrity Verification | `evidenceIsIntact()` เทียบ sha256 ถูกต้อง | ไม่ได้ถูกเรียกจากที่ใดนอกจากหน้าหลักฐาน · ไม่แยกกรณี "ไฟล์หาย" ออกจาก "ไฟล์ถูกแก้" | **สูง** | ยกเข้าบริการตรวจสอบ แยกสถานะไฟล์หาย/ถูกแก้ |
| 3 | Hash-before-sign / signed-version binding | หลักฐานเก็บ `document_version_id` + `document_hash` ของเวอร์ชันที่ลงนาม | **ไม่มีใครตรวจว่าสองค่านี้ยังตรงกัน** — ถ้า `document_hash` ไม่ตรงกับ `file_hash` ของเวอร์ชันที่ผูกไว้ ไม่มีอะไรจับได้ | **สูง** | ตรวจการผูกสามทาง: หลักฐาน ↔ เวอร์ชัน ↔ ไฟล์บนดิสก์ |
| 4 | Signer Identity Verification | บันทึก `signer_id` + snapshot ชื่อ/ตำแหน่ง | ไม่ตรวจว่า **ผู้สร้างเวอร์ชันที่ลงนาม คือผู้ลงนามคนเดียวกัน** | **สูง** — ธุรการเรนเดอร์เวอร์ชันแล้วผูกหลักฐานเป็นชื่อผู้อื่นได้ | ตรวจ `version.created_by === evidence.signer_id` |
| 5 | Authority Verification | `authority_snapshot` เก็บชื่อ ability ตอนลงนาม | ไม่ตรวจย้อนว่าผู้ลงนามมีอำนาจ **ณ วันที่ลงนาม** จริง · snapshot เป็น `null` ได้โดยไม่มีใครสังเกต | **สูง** — ลงนามโดยไม่มีอำนาจแล้วไม่มีใครรู้ | ตรวจซ้ำด้วย `hasAuthorityOver(..., $signedAt)` และแยก "หมดอายุแล้ววันนี้" เป็นคำเตือน |
| 6 | Signing Order Verification | ไม่มีแนวคิดลำดับการลงนามเลย | ลำดับที่คาดหวัง และการตรวจว่าลงนามตามลำดับ | กลาง | เก็บ `signing_sequence` ตอนลงนาม · ตรวจว่าเรียงตามเวลาจริง |
| 7 | Certificate Validation-ready | **ไม่มีอะไรเกี่ยวกับ certificate เลย** | ที่เก็บข้อมูลใบรับรอง และการตรวจ | **สูงมาก** — ถ้าเผลอแสดงคำว่า "ลายเซ็นดิจิทัล" จะเป็นการอ้างเท็จ | เพิ่มคอลัมน์ใบรับรอง (nullable) + `signature_type` · **ไม่แสดงผลใบรับรองเมื่อไม่มีใบรับรองจริง** |
| 8 | Certificate Expiry/Revocation-ready | ไม่มี | ตรวจอายุและการเพิกถอนใบรับรอง | สูง | ตรวจ `valid_from ≤ signed_at ≤ valid_to` และ `certificate_revoked_at` |
| 9 | Trusted Timestamp Validation-ready | ใช้ `TrustedClock` ของระบบ (นาฬิกาภายใน ไม่ใช่ TSA) | timestamp token จากผู้ให้บริการภายนอก และการตรวจ | กลาง | เพิ่มคอลัมน์ TSA (nullable) + ตรวจเมื่อมี · **ไม่อ้างว่ามี trusted timestamp เมื่อไม่มี** |
| 10 | Signature Evidence Package | หน้าหลักฐานคืนรายการดิบ | ชุดหลักฐานรวมที่ดาวน์โหลดและอ้างอิงได้ | กลาง | endpoint รายงานผลตรวจพร้อมหลักฐานครบชุด |
| 11 | Re-verification | ไม่มี | ตรวจซ้ำได้ทุกเมื่อ ไม่ใช่ตรวจครั้งเดียวตอนลงนาม | สูง | บริการตรวจคำนวณสดทุกครั้ง ไม่เก็บผลลง DB |
| 12 | Revocation Request Workflow | **ไม่มี** · `STATUS_CANCELLED` มีนิยามแต่ไม่มีใครตั้งค่า | ตาราง คำขอ เหตุผล และสถานะ | **สูง** — หนังสือที่ลงนามผิดพลาดถอนไม่ได้เลย | สร้าง `saraban_signature_revocations` + บริการ |
| 13 | Approve Revocation | ไม่มี | การอนุมัติที่แยกจากผู้ขอ | สูง | endpoint แยก + สิทธิ์แยก + `step_up` (แบบเดียวกับการทำลายเอกสาร INT-19) |
| 14 | Reject Revocation | ไม่มี | การปฏิเสธพร้อมเหตุผล | กลาง | endpoint แยก · คำขอที่ถูกปฏิเสธยังอยู่ในทะเบียน |
| 15 | Verification Report | ไม่มี | รายงานผลตรวจที่พิมพ์/แนบได้ | กลาง | endpoint รายงาน + แสดงในหน้าจอเดิม |
| 16 | Internal Verification UI | มีแค่รายการหลักฐานใน `DocumentTools.vue` | ผลตรวจ เหตุผลรายข้อ และปุ่มขอเพิกถอน | กลาง | ขยาย `DocumentTools.vue` เดิม ไม่สร้างหน้าใหม่ |
| 17 | Public Verification policy | คืน `is_valid` ที่คิดจาก finalized/cancelled/content_hash เท่านั้น | **ไม่ได้ตรวจลายเซ็นเลย** · หนังสือที่ไฟล์ถูกแก้หลังลงนามยังขึ้น `is_valid: true` ได้ | **สูง** | ให้สถานะสาธารณะมาจากบริการตรวจสอบตัวเดียวกัน แต่ **ไม่เปิดเผยรายละเอียดภายใน** |
| 18 | Verification API | ไม่มี | endpoint ตรวจสอบสำหรับผู้เชื่อมต่อ | กลาง | เพิ่มใน `api/saraban` และได้ `api/v1/saraban` ตามมาเอง |

## ความเสี่ยงที่พบระหว่างสำรวจ และไม่ได้อยู่ในรายการที่สั่ง

**RISK-64 — `is_valid` สาธารณะไม่ได้ดูลายเซ็นเลย**

`DocumentVerificationController::verify()` คิด `is_valid` จากสามอย่าง: ออกฉบับสมบูรณ์แล้ว ·
ไม่ถูกยกเลิก · เมทาดาทาไม่ถูกแก้ · **ไม่แตะไฟล์ ไม่แตะลายเซ็น**

> ไฟล์ PDF ที่ลงนามแล้วถูกสับเปลี่ยนบนดิสก์ หน้าตรวจสอบสาธารณะยังตอบว่า
> "ใช้อ้างอิงได้" — ซึ่งเป็นคำตอบที่ผิดในกรณีที่สำคัญที่สุด

**RISK-65 — `content_hash` ผนึกเฉพาะเมทาดาทา ไม่ผนึกไฟล์**

`contentHash()` แฮชเลขหนังสือ เรื่อง ประเภท หน่วยงาน วันที่ · **ไม่รวมแฮชของไฟล์**
การเปลี่ยนไฟล์จึงไม่ทำให้ `content_hash` เพี้ยน

**RISK-66 — ไม่มีอะไรตั้ง `STATUS_CANCELLED`**

สถานะมีนิยามและถูกใช้ตัดสินสิทธิ์ในสามที่ของ `DocumentPolicy` แต่ **ไม่มีเส้นทางใด
ในระบบที่ทำให้หนังสือเข้าสถานะนี้ได้** — โค้ดที่ตรวจสถานะซึ่งเกิดขึ้นไม่ได้ คือโค้ดที่
ไม่เคยทำงาน

## หลักที่ยึดในการแก้

1. **Electronic Signature ≠ Digital Signature** — ระบบวันนี้ทำ *electronic signature*
   (ลายเซ็นที่ผูกกับตัวตนที่ยืนยันแล้ว + หลักฐาน) **ไม่ใช่ digital signature**
   (การเข้ารหัสด้วยกุญแจส่วนตัวและใบรับรอง) · จะไม่มีที่ใดในระบบอ้างว่าเป็นอย่างหลัง
   จนกว่าจะมีหลักฐานเชิงรหัสวิทยาจริง
2. **ห้ามแสดงผลใบรับรองเมื่อไม่มีใบรับรอง** — ช่องใบรับรองว่าง = ไม่แสดงหัวข้อนั้นเลย
   ไม่ใช่แสดงว่า "ผ่าน"
3. **ห้าม VALID จากภาพลายเซ็นอย่างเดียว** — ต้องผ่านการผูกเวอร์ชัน แฮช ตัวตน และอำนาจ
4. **ตรวจฝั่ง server เท่านั้น** — หน้าจอแสดงผลที่ server ตัดสิน ไม่คำนวณเอง
5. **REUSE > EXTEND > MODIFY > CREATE** — ใช้ `AuthorityResolver` `AuditLogger`
   `StepUpAuthentication` `PolicyCenter` `DocumentPolicy` และหน้าจอเดิมทั้งหมด
