## วิธีใช้เอกสารนี้

เอกสารนี้เป็น **แบบบันทึกผล ไม่ใช่คู่มือ** — ผู้ทดสอบต้องเป็น **ผู้ปฏิบัติงานจริง**
ไม่ใช่ผู้พัฒนา และต้องกรอกผลด้วยตนเอง

> **ห้ามกรอก "ผ่าน" โดยไม่ได้ทำจริง** (SoT §23) — ทะเบียนหลักฐานของระบบออกแบบมา
> ให้ไม่ยอมรับ PASS ที่ไม่มีหลักฐาน เอกสารนี้ก็ยึดหลักเดียวกัน
> ถ้าทำไม่ได้เพราะติดขัด ให้เขียนว่า **"ทำไม่ได้"** พร้อมเหตุผล — มีค่ากว่าการ
> เขียนว่าผ่าน

**ก่อนเริ่ม** ผู้ดูแลระบบต้องทำสามข้อนี้ให้เสร็จ มิฉะนั้นผู้ทดสอบจะติดตั้งแต่ข้อแรก:

| # | สิ่งที่ต้องทำ | ทำไม |
|---|---|---|
| 1 | สร้าง container image ใหม่ (`docker compose build backend`) | การปกปิดข้อมูลต้องมี ghostscript (INT-18 · RISK-49) |
| 2 | ตั้งชุดเลขหนังสืออย่างน้อยหนึ่งชุด ที่ `/saraban/number-series` | ไม่มีชุดเลข = ลงนามไม่ได้ (INT-16) |
| 3 | มอบหมายสิทธิ์ `saraban.inbox.view` ให้บทบาทข้าราชการทั่วไป | ไม่งั้นหนังสือที่เวียนถึงเขาจะเปิดไม่เจอ (INT-13 · RISK-34) |

**ผู้ทดสอบที่ต้องมี** อย่างน้อย 4 บทบาท (คนละบัญชี):

- **ก.** เจ้าหน้าที่ธุรการ — สร้างหนังสือ ลงทะเบียนรับ
- **ข.** ผู้มีอำนาจลงนาม — ลงนาม ออกฉบับสมบูรณ์
- **ค.** ข้าราชการทั่วไป — รับหนังสือเวียน
- **ง.** ผู้ดูแลระบบ — นโยบาย ศูนย์เฝ้าระวัง การทำลายเอกสาร
