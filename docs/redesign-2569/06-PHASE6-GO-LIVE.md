# เฟส 6 — ทดสอบ ทดลองใช้คู่ขนาน และเปิดใช้จริง

## 6.1 ชุดทดสอบอัตโนมัติ (ต้องผ่านทั้งหมดก่อนเริ่ม 6.2)

| กลุ่ม | ขอบเขต |
|---|---|
| กฎการลา | ทุกประเภทการลา × ทุกประเภทบุคลากร: ผ่าน / ปฏิเสธ / แยกวันได้รับ-ไม่ได้รับเงินเดือน (เฟส 1–2) |
| สายอนุมัติ | การเลือกสายตามตารางอำนาจ และ authorization ทุกขั้น รวม IDOR ข้ามฝ่าย (เฟส 3) |
| บุคลากรและสิทธิ์ | ความเข้ากันได้ของตำแหน่ง วงจรบัญชี บทบาทที่ขัดกัน (เฟส 4) |
| ยอดวันลา | ledger ตรงกับยอดทุกสถานการณ์ ห้ามแก้ audit กันส่งซ้ำ (เฟส 5) |
| ภาษาไทย | ข้อความ validation/error/สถานะ/แจ้งเตือน/PDF/CSV เป็นภาษาไทย (07) |
| ถดถอย | test เดิมทั้งชุดยังผ่าน (ปัจจุบันราว 666 tests) |

## 6.2 ทดลองใช้คู่ขนานกับระบบกระดาษ — 1 ภาคเรียน

- เลือก 2 ฝ่ายนำร่อง (เสนอ: ฝ่ายบริหารทรัพยากร และแผนกวิชา 1 แผนก) บุคลากรยื่นลาทั้งในกระดาษและในระบบ
- งานบุคลากรเทียบทุกสัปดาห์: ผู้อนุมัติ จำนวนวัน วันได้รับ/ไม่ได้รับเงินเดือน ยอดคงเหลือ กับทะเบียนคุมวันลาเดิม
- ความต่างทุกรายการบันทึกเป็นประเด็น ต้องหาสาเหตุ (กฎผิด / ข้อมูลผิด / คนกรอกผิด) และแก้ก่อนขยาย
- เกณฑ์ผ่าน: 4 สัปดาห์ติดต่อกันไม่มีความต่างที่เกิดจากระบบ

## 6.3 เตรียมข้อมูลจริง

| รายการ | ตรวจด้วย | เกณฑ์ |
|---|---|---|
| นโยบายการลาครบทุกประเภทบุคลากร × ประเภทการลา | `leave:policy-coverage` | 0 ช่องว่าง |
| ตารางอำนาจครบ | `leave:authority-dry-run` | 0 กรณีหาไม่พบ |
| ข้อมูลบุคลากรครบ | `personnel:completeness` | 0 รายการขาด |
| หัวหน้าทุกหน่วยมีคำสั่งรองรับ | รายงาน `org_unit_managers` ที่ไม่มีเลขคำสั่ง | 0 |
| ยอดยกมาตรงทะเบียนเดิม | งานบุคลากรลงนามรับรองรายบุคคล | 100% |
| ทบทวนสิทธิ์รอบแรก | `access_reviews` | ผอ. รับรองแล้ว |

## 6.4 วันเปิดใช้

1. สำรองฐานข้อมูล (mysqldump) และทดสอบกู้คืนบนเครื่องอื่นก่อน
2. ประกาศหยุดรับใบลากระดาษตั้งแต่วันที่กำหนด ใบลากระดาษที่ค้างให้งานบุคลากรบันทึกแทนในระบบ
3. `php artisan migrate --force` → `php artisan audit:protect` ด้วยบัญชีฐานข้อมูลที่มีสิทธิ์สร้าง trigger → `audit:protect --check` → `optimize:clear` → คำสั่งตรวจในข้อ 6.3 ทั้งหมดอีกครั้ง
4. เปิดสายอนุมัติใหม่และปิด role fallback
5. ติดตามแจ้งเตือนกระทบยอดและ audit chain ทุกวันในสัปดาห์แรก

## 6.5 แผนย้อนกลับ

| สถานการณ์ | ทำ |
|---|---|
| สายอนุมัติเลือกผิด | ปิดใช้แถว `leave_authority_rules` ที่ผิด (ไม่ลบ) ใบลาที่สร้างไปแล้วให้ผู้มีอำนาจตัดสินเป็นรายใบ |
| ยอดวันลาเพี้ยน | ระหว่างเขียนคู่ขนาน กลับไปใช้ยอดเดิมได้ทันที หลังสลับแล้วแก้ด้วย `REVERSAL` / `ADJUST` |
| ระบบใช้ไม่ได้ทั้งระบบ | กลับไปใช้ใบลากระดาษ บันทึกย้อนหลังเมื่อระบบกลับมา (ลาป่วย/ลาคลอดยื่นย้อนหลังได้อยู่แล้ว ลาประเภทอื่นใช้การบันทึกแทนของเจ้าหน้าที่) |

## 6.6 การอบรม

- บุคลากร: ยื่นลา ยกเลิกลา รายงานตัวกลับ ดูยอดคงเหลือ (คู่มือภาษาไทย 1 หน้า + วิดีโอสั้น)
- หัวหน้าและผู้บริหาร: อนุมัติ เรียกตัวกลับ ทำการแทน
- งานบุคลากร: ตรวจสอบ ลงทะเบียนคุม ส่งต่อภายนอก ปรับยอด ปิดงวด อ่านรายงานกระทบยอด
