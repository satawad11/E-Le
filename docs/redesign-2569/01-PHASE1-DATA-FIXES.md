# เฟส 1 — แก้ข้อมูล (ไม่เปลี่ยน schema)

> เปลี่ยนเฉพาะข้อมูลผ่าน migration แบบข้อมูล (data migration) ที่ย้อนกลับได้ ไม่ขัด Production Freeze
> ค่าทุกค่าในเฟสนี้ต้องมาจากเอกสารที่ยืนยันแล้ว ถ้ายังไม่มีคำตอบเฟส 0 ให้ทำเฉพาะข้อที่ระบุว่า "ทำได้ทันที"

## 1.1 ลาล่วงหน้า 60 วันของลาอุปสมบท / ลาไปประกอบพิธีฮัจญ์ — **ทำแล้ว**

> migration `2026_10_19_110000_enforce_ordination_hajj_notice_period.php` · test `OrdinationNoticePeriodTest`
> พบและแก้ร่วมด้วย: `leave:sync-quotas` เดิมวนนโยบายทุกรุ่นตาม id ทำให้รุ่นที่ปิดแล้วเขียนทับ quota/leave_policy_id ของปีปัจจุบันได้ — แก้ให้ข้ามรุ่นที่ปิดแล้ว

**ที่พบ:** `leave_types.notice_period_days` = 60 แต่ `leave_policies.notice_period_days` = 0 ทุกประเภทบุคลากร ระบบตรวจจากนโยบาย (`LeavePolicyService::assertEligible`) จึงไม่บังคับ 60 วัน

**อ้างอิง:** ระเบียบฯ และคู่มือหัวข้อ 6.2 — ยื่นก่อนวันอุปสมบทหรือก่อนวันเดินทางไม่น้อยกว่า 60 วัน และหัวข้อ 6.3 — ถ้ามีเหตุพิเศษให้ผู้มีอำนาจพิจารณาเป็นรายกรณี

**การแก้:**
- ปิดนโยบายรุ่นเดิมด้วย `effective_to` = วันก่อนใช้ แล้วสร้างรุ่นใหม่ `notice_period_days` = 60 (ห้ามแก้ทับ — PROJECT_RULES ข้อ 7)
- ใบลาที่ยื่นไปแล้วไม่กระทบ เพราะผูกกับนโยบายรุ่นเดิม
- กรณีเหตุพิเศษตามหัวข้อ 6.3: เฟส 2 เพิ่ม "ขอยกเว้นกำหนดยื่นล่วงหน้า" พร้อมเหตุผล ให้ผู้มีอำนาจตัดสิน ระหว่างนี้ใช้การบันทึกการลาแทนของเจ้าหน้าที่ (มี `skipTimingRules` อยู่แล้ว)

**Test:** ยื่นลาอุปสมบทล่วงหน้า 59 วันถูกปฏิเสธพร้อมข้อความภาษาไทย / 60 วันผ่าน / ใบลาเดิมที่ผูกรุ่นเก่ายังอนุมัติต่อได้

## 1.2 ลาคลอดบุตร — รอ D-02

สร้างนโยบายรุ่นใหม่ตามคำตอบ D-02 โดยใช้ `effective_from` = วันที่ระเบียบฉบับที่ใช้มีผล

## 1.3 สิทธิ์การลาของบุคลากรที่ไม่ใช่ข้าราชการ — รอ D-03, D-04

- ตรวจและแก้ค่าที่ขัดกันเอง เช่น ลูกจ้างชั่วคราว ลาพักผ่อน 6 วัน แต่ `max_accumulated` = 30
- สร้างนโยบายของประเภทบุคลากรใหม่ **ครบทุกประเภทการลา** ก่อนผูกบุคลากรคนแรก ประเภทการลาที่ไม่มีสิทธิ์ให้สร้างแถว **เปิดใช้ โควตา 0** (ไม่ใช่แถวปิดใช้ เพราะ `resolve()` ค้นเฉพาะแถวเปิดใช้ แล้วจะสร้างค่าระดับข้าราชการให้เอง)

## 1.5 หัวหน้าหน่วยงาน (`org_unit_managers`)

- กรอกหัวหน้าของ **ทุกฝ่าย ทุกงาน ทุกแผนกวิชาพร้อมกันในครั้งเดียว** ตามคำสั่งแต่งตั้งจริง พร้อมเลขที่และวันที่คำสั่ง
- ทำทีละส่วนไม่ได้ เพราะหน่วยที่ยังไม่มีหัวหน้าจะตกไปใช้ fallback ตามชื่อบทบาท (รองฯ ทุกคนอนุมัติได้ทุกฝ่าย) — `ORG-POSITION-ACCESS-MAPPING.md` ข้อ 5.3
- วันเดียวกันให้เพิ่ม `permission_scopes` = `ORGANIZATION` ให้รองฯ และงานบุคลากร ตามที่ตัดสินแล้วในข้อ 6.1 Q6 ของเอกสารเดิม
- หลังกรอกครบ ตั้ง `workflow.approver_role_fallback` = `false` เพื่อให้หน่วยที่ไม่มีหัวหน้า **ค้างรอ** แทนการส่งให้คนที่ไม่เกี่ยวข้อง และแจ้งเตือนงานบุคลากร

**ห้ามสร้างคำสั่งแต่งตั้งขึ้นเอง** — ต้องได้รายชื่อจากงานบุคลากร
