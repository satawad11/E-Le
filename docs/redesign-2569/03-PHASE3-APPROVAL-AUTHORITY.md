# เฟส 3 — ตารางอำนาจอนุญาตและสายอนุมัติตามหน่วยงานจริง

> ต้องเพิ่มตาราง 1 ตารางและคอลัมน์ใน `approval_steps` — ต้องได้รับอนุมัติข้อยกเว้น Production Freeze
> ค่าในตารางอำนาจต้องมาจาก D-01 เท่านั้น

## 3.1 ปัญหาปัจจุบัน

- สายอนุมัติ `leave` มี 3 ขั้น ทุกขั้นใช้ `approver_type` = `ROLE` (หัวหน้าบุคลากร → รองผู้อำนวยการ → ผู้อำนวยการ) ใช้กับทุกประเภทการลาและทุกจำนวนวัน
- ผลคือ รองผู้อำนวยการ **ทุกคน** อนุมัติได้ **ทุกฝ่าย** ไม่มีขั้นหัวหน้าแผนก/หัวหน้างาน และการลาที่เกินอำนาจวิทยาลัยถูกอนุมัติจบในวิทยาลัย
- ตัว resolver รองรับการหาผู้อนุมัติตามหน่วยงานอยู่แล้ว (`DEPARTMENT_HEAD`, `DIVISION_DIRECTOR`, `DIRECTOR`, `ORG_UNIT_MANAGER`, `HR_OFFICER` ใน `ApproverResolverService`) แต่ข้อมูลยังไม่ได้ใช้

## 3.2 แบบจำลอง

```
ใบลา ──► leave_authority_rules (เลือกตาม ประเภทการลา × ประเภทบุคลากร × จำนวนวัน × วันที่ยื่น)
              │
              └──► chain_code ──► approval_steps (ขั้นตอนของสายนั้น ตามลำดับ)
                                      │
                                      └──► ApproverResolverService (หาตัวคนจาก org_unit_managers / user_delegations ณ วันที่)
                                               │
                                               └──► leave_approvals (snapshot ผู้อนุมัติ ณ เวลาสร้าง — มีแล้ว)
```

### ตารางใหม่ `leave_authority_rules`

| คอลัมน์ | ความหมาย |
|---|---|
| `uuid` | public id |
| `leave_type_id` | ประเภทการลา |
| `personnel_type_id` | nullable = ทุกประเภทบุคลากร |
| `requester_capacity` | nullable / `staff` / `unit_head` / `deputy` / `director` — การลาของหัวหน้าและผู้บริหารใช้สายต่างจากบุคลากรทั่วไป |
| `min_days`, `max_days` | ช่วงจำนวนวัน (รวมใบต่อเนื่องและใบที่ต่อเวลา) |
| `chain_code` | สายอนุมัติที่ใช้ |
| `final_authority` | `college` = จบในวิทยาลัย / `external` = ส่งต่อหน่วยงานภายนอก |
| `external_authority_name` | ชื่อตำแหน่งผู้มีอำนาจภายนอก เช่น ตามคำสั่ง สอศ. (ข้อความที่พิมพ์ในบันทึกเสนอ) |
| `reference_document` | เลขที่และวันที่คำสั่งมอบอำนาจ — **บังคับกรอก** |
| `effective_from`, `effective_to`, `is_active` | มีรุ่น ห้ามแก้ทับ |

**กฎการเลือก:** ถ้าพบมากกว่า 1 แถว ให้ใช้แถวที่ระบุเงื่อนไขละเอียดที่สุด ถ้า **ไม่พบเลย ระบบไม่รับใบลา** และแจ้งงานบุคลากร (ไม่ตกไปสายเริ่มต้น) — มี test ยืนยัน

### เพิ่มใน `approval_steps`

| คอลัมน์ | ความหมาย |
|---|---|
| `action_kind` | `approve` (อนุญาต/ไม่อนุญาต) · `comment` (เสนอความเห็น) · `acknowledge` (รับทราบ — ใช้กับการรายงานลา) · `check` (ตรวจสอบและลงทะเบียนคุม) · `forward_external` (ส่งต่อและบันทึกผลจากภายนอก) |
| `skip_when_requester_is_approver` | ข้ามขั้นนี้เมื่อผู้ลาคือผู้อนุมัติขั้นนี้เอง เช่น หัวหน้าแผนกลา → ข้ามขั้นหัวหน้าแผนก ไปที่รองฯ (แทนการอนุมัติของตนเอง) |

## 3.3 สายอนุมัติมาตรฐาน (ตามแผนผังขั้นตอนการลาในคู่มือ)

| chain_code | ขั้นตอน | ใช้กับ |
|---|---|---|
| `leave.standard` | ① เจ้าหน้าที่งานบุคลากรตรวจสอบวันลาและลงทะเบียนคุม (`HR_OFFICER`, check) → ② หัวหน้าแผนก/งานต้นสังกัด (`DEPARTMENT_HEAD`, comment) → ③ รองผู้อำนวยการที่ได้รับมอบหมายดูแลฝ่ายนั้น (`DIVISION_DIRECTOR`, comment หรือ approve ตามคำสั่ง) → ④ ผู้อำนวยการ (`DIRECTOR`, approve) | การลาที่อยู่ในอำนาจวิทยาลัย |
| `leave.delegated_deputy` | ① → ② → ③ (approve) | ประเภท/จำนวนวันที่ ผอ. มอบอำนาจให้รองฯ อนุญาต (ถ้า D-01 มี) |
| `leave.external` | ① → ② → ③ → ④ (comment) → ⑤ ส่งต่อผู้มีอำนาจภายนอก (`forward_external`) | การลาที่เกินอำนาจวิทยาลัย |
| `leave.notification` | ① (check) → ② → ③ → ④ ทุกขั้น acknowledge | ลาเข้ารับการตรวจเลือกหรือเข้ารับการเตรียมพล |
| `leave.director_own` | ตาม D-01 | การลาของผู้อำนวยการเอง |
| `cancellation.*` | ใช้ชุดเดียวกับสายที่อนุมัติใบลาเดิม (snapshot) | การขอยกเลิกวันลา |

- รองฯ ที่ดูแลหลายฝ่าย ได้ขั้น ③ ของทุกฝ่ายที่ได้รับมอบ เพราะ resolver อ่าน `org_unit_managers` ณ วันที่ — ไม่ต้องมีตำแหน่งแยกตามฝ่าย
- ผู้รักษาราชการแทน / ปฏิบัติราชการแทน: ใช้ `user_delegations` ที่อนุมัติแล้ว (มีแล้ว) และพิมพ์ฐานะ "รักษาราชการแทน" ในใบลา (มี `acting capacity` แล้ว)

## 3.4 ขั้น "ส่งต่อผู้มีอำนาจภายนอก"

ระบบไม่ได้เชื่อมกับหน่วยงานภายนอก ขั้นนี้จึงเป็นการ **บันทึก** ไม่ใช่การอนุมัติในระบบ:
1. เมื่อ ผอ. ลงนามเสนอ ระบบออกบันทึกเสนอขออนุญาต (PDF ผ่าน Document Engine) พร้อมเลขที่หนังสือจากสารบรรณ
2. เจ้าหน้าที่บันทึก "ส่งแล้ว" (เลขที่หนังสือ วันที่ส่ง)
3. เมื่อได้รับผล เจ้าหน้าที่บันทึกผล อนุญาต/ไม่อนุญาต พร้อมแนบหนังสือตอบ — **ต้องแนบเอกสารจึงบันทึกได้** และผู้ตรวจคนที่สองยืนยัน (D-08)
4. ระหว่างรอผล วันลาอยู่ในสถานะ "จองไว้" ใน ledger ไม่ใช่ "ใช้แล้ว"
5. ครบ 30 วันยังไม่มีผล แจ้งเตือนงานบุคลากร (ค่าตั้งได้)

## 3.4.1 ความคืบหน้า (18/10/2569)

- เจ้าของระบบกำหนดลำดับอำนาจ: ผู้อำนวยการ (สูงสุด) → รองผู้อำนวยการ → หัวหน้างาน/หัวหน้าแผนก (D-01 บางส่วน)
- ทำแล้ว: คำสั่ง `php artisan leave:apply-standard-chain` ตั้งสาย `leave.standard` ในตาราง `approval_steps` เดิม (ไม่เปลี่ยน schema) 4 ขั้น: งานบุคลากร (`HR_OFFICER`) → หัวหน้างาน/แผนก (`DEPARTMENT_HEAD`) → รองผู้อำนวยการ (`DIVISION_DIRECTOR`) → ผู้อำนวยการ (`DIRECTOR`)
  - `--check` ตรวจอย่างเดียว: **ต้องแก้ก่อน** = หน่วยงานไม่มีหัวหน้า, บุคลากรที่หาผู้อนุมัติไม่พบ · **ข้อสังเกต** = ผู้อนุมัติซ้ำกับขั้นก่อนหน้า, ใบลาของผู้อำนวยการเอง
  - ไม่ยอมตั้งสายถ้ายังมีรายการต้องแก้ เว้นแต่ใส่ `--force` · บันทึก audit ทุกครั้ง · ใบลาที่ยื่นไปแล้วไม่กระทบ
- ลำดับใช้งาน: นำเข้ารายชื่อบุคลากร → `org:apply-structure` → กรอกหัวหน้าทุกหน่วยงาน → `leave:apply-standard-chain --check` → `leave:apply-standard-chain` → ปิด `workflow.approver_role_fallback`
- **ทำแล้ว — ส่งต่อหลังผู้อำนวยการอนุมัติ** (เจ้าของระบบ: "ให้ผู้อำนวยการอนุมัติก่อน แล้วค่อยนำส่งต่อ"): `LeaveExternalForwardingService` ติดสถานะในใบลา (`leaves.meta_data.external_forwarding` ไม่เปลี่ยน schema) เมื่อ (ก) นโยบายมี `requires_external_approval` (ข) วันลาประเภทนั้นในปีเกิน `external_approval_after_days` หรือ (ค) ผู้ลาคือผู้อำนวยการ · งานบุคลากรบันทึกการส่ง (ส่งถึง เลขที่ วันที่) และผล (เลขที่หนังสือตอบ วันที่) ที่แท็บ "รอส่งต่อผู้มีอำนาจ" ในศูนย์งานกำกับการลา · ผลไม่อนุญาต = ยกเลิกเอกสารและคืนวันลาอัตโนมัติ · ผู้ลาเห็นสถานะ "ผู้อำนวยการอนุมัติแล้ว รอผลจากผู้มีอำนาจ" · ประวัติทุกขั้นอยู่ใน `leave_audit_logs`
- ตั้งตามคู่มือแล้ว (migration `2026_10_19_160000`): ลาติดตามคู่สมรส, ลาไปปฏิบัติงานในองค์การระหว่างประเทศ, ลาป่วยของข้าราชการและลูกจ้างประจำที่รวมในปีเกิน 60 วัน · ประเภทอื่นเปิดได้ที่นโยบายการลา
- ยังไม่ทำ: ตาราง `leave_authority_rules` (เลือกสายตามประเภทการลาและจำนวนวัน) และการออกบันทึกเสนอเป็น PDF

## 3.5 การย้ายจากสายเดิม

1. สร้างสายใหม่ทั้งหมดแบบปิดใช้งาน และกรอก `leave_authority_rules` ตาม D-01
2. รันคำสั่ง `leave:authority-dry-run` (อ่านอย่างเดียว) ที่จำลองการเลือกสายของ **ทุกบุคลากร × ทุกประเภทการลา** แล้วรายงานกรณีที่หาสายหรือหาผู้อนุมัติไม่พบ — ต้องเป็นศูนย์
3. เปิดใช้สายใหม่กับใบลาที่ยื่น **หลัง** วันเปิดใช้ ใบลาที่ค้างอยู่ใช้ snapshot เดิมจนจบ
4. ปิด `workflow.approver_role_fallback`
5. Workflow engine ที่เดินคู่ขนาน (`LeaveWorkflowShadow`) ต้องอ่านสายเดียวกัน — การ cutover engine (05-4) ยังเป็นเรื่องแยก

## 3.6 Automated tests

- เลือกสายถูกตาม ประเภทการลา × ประเภทบุคลากร × จำนวนวัน รวมขอบเขตวันพอดีเพดาน (60 / 60.5 / 61 วัน)
- ไม่พบกฎ → ใบลาถูกปฏิเสธ ไม่ตกไปสายเริ่มต้น
- รองฯ ฝ่าย ก อนุมัติใบลาของฝ่าย ข ไม่ได้ (authorization / IDOR) / รองฯ ที่ได้รับมอบ 2 ฝ่ายอนุมัติได้ทั้งสอง
- หัวหน้าแผนกลา → ข้ามขั้นตนเอง / คนเดียวกันอนุมัติสองขั้นติดกันของใบเดียวกันไม่ได้
- ขั้น forward_external บันทึกผลไม่ได้ถ้าไม่แนบหนังสือตอบ / ผู้บันทึกกับผู้ยืนยันเป็นคนเดียวกันไม่ได้
- คำสั่งหัวหน้าหมดอายุระหว่างใบลาค้าง → ใบลาที่ค้างยังใช้ snapshot เดิม ใบลาใหม่ไปหาผู้รับตำแหน่งใหม่

## Definition of Done เฟส 3

- [ ] `leave_authority_rules` ทุกแถวมี `reference_document`
- [ ] dry-run ไม่มีกรณีหาสายหรือผู้อนุมัติไม่พบ
- [ ] หน้าจอจัดการตารางอำนาจเป็นภาษาไทย การแก้ต้องผ่านผู้ตรวจคนที่สอง และบันทึก audit
- [ ] แบบฟอร์มใบลาพิมพ์ชื่อและฐานะผู้ลงนามแต่ละขั้นถูกต้อง (ตำแหน่ง + "รักษาราชการแทน" เมื่อเป็นผู้รักษาการ)
